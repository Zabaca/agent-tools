# intent

Capture session intent, detect drift, log transitions. A focus layer on top of Claude Code sessions.

## What it does

- `/intent <text>` — anchor the session to a stated goal
- `/intent done` / `--update <text>` / `--abandon` — explicit transitions, logged with timestamps
- `/intent history` / `active` — look across sessions
- **UserPromptSubmit hook** — silently injects the active intent into the agent's context on every turn, so the agent sees it and can self-check for drift
- **Statusline contribution** — optional one-line display of the active intent

## Why

Sessions sprawl when scope morphs invisibly. Explicit intents make the "is this still what we're doing?" question answerable in real time, and the transition log captures the structure of how work actually moved across goals.

Data lives in a local SQLite DB at `~/.intent/data.db` — single-writer-friendly, no lock-file collisions across concurrent Claude Code sessions.

## Setup

Install via marketplace (this repo's `.claude-plugin/marketplace.json`).

The SessionStart hook runs `bun install` on first session in a new clone. After that, `/intent` works.

### Statusline integration (optional)

To show the active intent in your statusline, add this to your statusline script (typically `~/.claude/statusline-command.sh`):

```bash
# After your existing line 1 output, before exit:
session_id=$(echo "$input" | jq -r '.session_id // empty')
intent_line=$(${CLAUDE_PLUGIN_ROOT}/statusline-contribute.sh "$session_id" 2>/dev/null || true)
[ -n "$intent_line" ] && printf "\n%s" "$intent_line"
```

(Replace `${CLAUDE_PLUGIN_ROOT}` with the actual installed path of this plugin.)

## Data flow

```
/intent <text>                      → src/cli.ts set
   ↓
SQLite (~/.intent/data.db)
   ↓ (read on every user prompt by UserPromptSubmit hook)
agent context (additionalContext: "Session intent: …")
   ↓ (read by statusline)
visible reminder at bottom of terminal
   ↓ (downstream: ingested by zabaca/data pipeline → dashboard)
operator-pulse view
```

The plugin **never writes to the data warehouse directly**. The downstream `zabaca/data` pipeline ingests `~/.intent/data.db` via dlt into `data/raw/session_intents.duckdb`, then dbt + Evidence.

## Commands

| Command | Effect |
|---|---|
| `/intent <text>` | Set initial intent for current session |
| `/intent set <text>` | Same |
| `/intent done [--note "..."]` | Mark current intent complete |
| `/intent abandon [--reason "..."]` | Consciously drop current intent |
| `/intent update <text>` | Transition: close current, open new, link them |
| `/intent status` | Current + history within this session |
| `/intent history [--repo X --days N --limit N]` | Cross-session history |
| `/intent active` | All currently-active intents (across sessions) |

## Schema (SQLite)

```
intents
─────────────────
  id               text PRIMARY KEY (cuid2)
  session_id       text NOT NULL
  stated_at        integer (unix timestamp)
  intent_text      text NOT NULL
  status           text                       -- active | completed | abandoned | superseded
  completed_at     integer
  completion_note  text
  superseded_by    text                       -- FK to intents.id (next intent in chain)
  cwd              text                       -- launch cwd of the session
  created_at       integer
  updated_at       integer
```

## Migrations

`drizzle/0000_init.sql` is generated by `bun run db:generate`. Drizzle handles schema diffing — to evolve the schema, edit `src/db/schema.ts` and regenerate.
